=== title
heading: Vibe coding 與 agent 工具
sub: 什麼時候放手，放手之後誰負責驗證
> 這一章談 vibe coding，以及代理型的開發工具。我們要回答一個比工具本身更重要的問題：自主程度與風險，要怎麼搭配？

=== bullets
heading: 什麼是 vibe coding
- 2025 年 2 月出現的詞：用自然語言引導 AI 寫出整個專案
- 人的角色從手寫程式，變成引導與驗收
- 幾乎不讀程式碼，靠描述與執行結果來回修正
> vibe coding 這個詞在二零二五年二月出現，指的是用自然語言引導 AI 產生整個專案，人的角色從手寫程式，變成引導與驗收；幾乎不讀程式碼，靠描述和執行結果來回修正。

=== compare
heading: 適合與不適合
col: 適合
- 快速原型：週末做出可以展示的版本
- 不熟悉的技術：先看看可能性
- 不重要的東西：內部小工具、自己玩的遊戲
col: 不適合直接上線
- 處理敏感資料
- 企業級的正式軟體
- 原因：模型不能被問責
> 它適合三種情境：快速原型，例如週末內做出可以給利害關係人看的展示，之後再用自己的方式做真正的版本；不熟悉的技術，先讓工具做出一個原型看看可能性；以及不重要的東西，例如內部小工具，或自己玩的遊戲。
> 但要明確警告：處理敏感資料，或企業級的正式軟體，不要這樣做就直接上線，因為模型不能被問責。

=== bullets
heading: 代理型編輯器的特點
- 代理模式：自己探索程式庫、讀文件、改多個檔案、執行指令
- 專案層級的 context 與規則檔
- 自己挑選 context，避免雜訊稀釋焦點
- 較新、推理型的模型通常較貴；把 context 拉到最大，帳單可能暴增
> 代理型的 AI 編輯器有幾個特點。代理模式下，AI 可以自己探索程式庫、讀文件、修改多個檔案、執行終端機指令，使用者負責監督與核准。它支援專案層級的上下文與規則檔，也鼓勵你自己挑選要加入的檔案，避免雜訊稀釋焦點。
> 費用也要注意：較新或推理型的模型通常比較貴，把上下文拉到最大的模式，帳單可能因此暴增。
> 一個實作經驗是：初始的提示詞越完整，例如先講清楚語言、框架、規則、操作方式與程式碼品質的要求，後面的來回就越少。以做一個小遊戲為例，先想清楚遊戲的概念，再寫一份很詳細的首輪提示詞，第一次產出就能直接執行；之後再用回饋修正問題，例如木頭互相重疊。另一個常聽到的經驗是，專案變大之後，工具大約能帶你走到八成，剩下要手動處理；這是經驗談，不是量測。

=== figure
heading: 自主程度的階梯
src: autonomy-ladder.svg
caption: 越往上越快，但驗證責任越不能外包
> 這張圖是自主程度的階梯：補全、聊天、代理程式、自動模式、全自動。越往上越快，但風險也越高。vibe coding 和工程化地使用代理程式，差別不在工具，而在誰負責驗證。護欄要隨著自主程度加重：差異審查、把測試當規格、權限分級與白名單、沙箱與可還原的分支，最後是成本上限。

=== table
heading: 護欄與它擋住的風險
| 護欄 | 擋住的風險 |
| git 分支或 worktree | 改壞了可以整個丟掉 |
| 測試當完成條件 | 「看起來完成」但其實壞掉 |
| 目錄白名單、指令白名單 | 改到不該改的地方、執行危險指令 |
| 成本與步數上限 | 失控的迴圈與帳單 |
| diff review | 夾帶的非預期修改 |
> 這些護欄大多可以自動檢查。分支或工作樹，讓改壞了可以整個丟掉；把測試當完成條件，擋住看起來完成、其實壞掉的情況；目錄與指令白名單，擋住改到不該改的地方或執行危險指令；成本與步數上限，擋住失控的迴圈與帳單；差異審查，擋住夾帶的非預期修改。其中成本與步數上限，就是從上下文拉到最大、帳單暴增學到的教訓。

=== quiz
heading: 檢查點
q: 團隊想讓代理程式以最高自主度處理 repo。哪個決策最符合風險分級？
- 所有專案一律用全自動
- 所有專案一律禁止
- * 依風險分級：可還原、無敏感資料的任務用較高自主度並加護欄；金流、權限、個資、不可逆操作要人工確認
- 讓代理程式自己判斷風險等級
> 檢查點：團隊想讓代理程式以最高自主度處理程式庫，哪個決策最合理？答案是第三個，依風險分級。讓代理程式自己判斷風險，等於把護欄交給被護欄限制的對象。
> 風險不是二選一。一份分級政策的示意可以分成三層。拋棄式、無敏感資料、可還原的原型，可以用自動模式，搭配分支、測試關卡與成本上限。有使用者、但可以回滾的內部服務，每個指令都要確認，並要求差異審查、測試與目錄白名單。金流、權限、個資或不可逆的操作，修改只由人來做，需要兩人審查，代理程式沒有寫入權限。

=== end
heading: 重點回顧
- vibe coding 適合原型、探索與不重要的東西
- 差別不在工具，而在誰負責驗證
- 護欄隨自主程度加重，大多可以自動檢查
> 回顧一下。vibe coding 適合原型、探索與不重要的東西；差別不在工具，而在誰負責驗證；護欄要隨自主程度加重，而且大多可以自動檢查。
> 思考練習會請你回答技術長的問題：vibe coding 能不能用在我們公司？什麼時候可以，什麼時候不行？提示是：用可還原性、敏感度與爆炸半徑來決定自主程度；並強調責任，AI 不能被問責，簽名合併的人要負責。最後，記錄介入次數與回滾次數，用數據決定是否放寬。
