=== title
heading: 取樣：temperature 與 top-p
sub: 模型輸出的是機率分佈，不是答案；取樣策略是你可以調的旋鈕
> 這一章談取樣。上一章說過，模型每一步輸出的是下一個 token 的機率分佈。那最後是怎麼從分佈裡選出一個 token 的？答案是取樣器，而取樣策略是你可以調的旋鈕，不是模型本身的一部分。

=== steps
heading: 從分數到下一個 token
- 模型對詞表裡每個 token 算出一個原始分數（logit）
- softmax 把分數轉成機率分佈
- 取樣器依策略選出下一個 token，接回 context 再算下一步
note: 想成 argmax 與隨機分佈抽樣之間的一個連續旋鈕
> 流程有三步。第一步，模型對詞表裡的每一個 token 算出一個原始分數。第二步，用一個歸一化函數把分數轉成機率分佈。第三步，取樣器依照你設定的策略，選出下一個 token，接回 context，再算下一步。
> 你可以把它想成一個連續的旋鈕：一端是永遠挑最高分的選法，另一端是完全照機率隨機抽。

=== compare
heading: 兩個旋鈕
col: temperature
- 取樣前把分數做縮放
- 越低，分佈越尖，越接近永遠選最高分
- 越高，分佈越平，冷門候選更容易被抽中
col: top-p
- 由高到低累加機率，直到達到 p
- 只保留這些候選，其餘截斷後重新正規化
- p 越小，候選越少，輸出越保守
> 第一個旋鈕是 temperature。它在取樣前縮放分數：溫度越低，分佈越尖，幾乎總是選最高分的候選；溫度越高，分佈越平，冷門的候選就更容易被抽中。
> 第二個旋鈕是累積機率取樣，也就是 top-p。它把候選依機率由高到低累加，加到門檻 p 為止，只在這些候選裡抽，其他的直接截斷，再重新正規化。p 越小，候選越少，輸出越保守。

=== bullets
heading: 動手：取樣實驗
- 情境：模型剛寫完 `v.`，下一個 token 有幾個候選
- 調高 temperature，看冷門候選的機率怎麼上升
- 調低 top-p，看哪些候選被直接截斷
note: 實驗裡的分數是教學用的假資料
> 頁面上有一個取樣實驗。情境是模型剛寫完一個變數名稱加一個點，接下來要接哪個方法名稱。候選裡有幾個常見的方法，也有一個很冷門的「banana」。
> 你可以試著把溫度調高，看冷門候選的機率怎麼上升；再把 top-p 調低，看哪些候選被直接截斷。實驗裡的分數是教學用的假資料，重點是感受分佈形狀的變化。

=== big
heading: 常見誤解
text: temperature 設為 0，也不保證每次輸出都一樣
> 接下來是這一章最重要的觀念：把溫度設成零，並不保證每次輸出都完全一樣。

=== bullets
heading: 為什麼溫度為零仍然不確定
- 浮點數加法的順序不同，結果有微小差異
- 批次大小與核心選擇不同、多張 GPU 並行歸約的順序不同
- 兩個機率很接近的候選，微小差異就會翻轉選擇，之後整段分岔
note: 部分 API 也限制或不開放某些取樣參數，以官方文件為準
> 原因在數值計算。浮點數加法的順序不同，結果就會有微小差異；而服務端的批次大小、核心選擇、多張 GPU 並行歸約的順序，都可能改變加法順序。
> 當兩個候選的機率非常接近時，這一點點差異就足以翻轉選擇，而一旦某一步選了不同的 token，後面整段文字就會分岔。
> 這對工程有直接的意義：代理程式的評測，不能假設單次執行可以重現。同一題要跑多次，報告結果的分佈與變異，這是第八週的主題。

=== quiz
heading: 檢查點
q: 同一個提示詞、temperature 為 0，代理程式連續兩次產出了不同的修改。最合理的第一個判斷是？
- API 有錯誤，應該向供應商回報
- * 溫度為零在實務上不保證逐 token 可重現；評估時應多次執行並看分佈
- 必須把 temperature 設成負數才能確定
- 代表模型沒有收斂，需要重新訓練
> 來看檢查點。同一個提示詞、溫度為零，代理程式兩次產出了不同的修改，最合理的判斷是什麼？
> 答案是第二個。溫度為零在實務上不保證可以重現。正確的做法，是把代理程式當成一個隨機系統，用多次試驗與統計方法評估，並且在系統層用測試來驗證結果，而不是期待它每次都一樣。

=== end
heading: 重點回顧
- 模型輸出分數，取樣器決定下一個 token
- temperature 控制分佈的尖銳程度，top-p 控制候選的範圍
- 溫度為零也不保證可重現：評測要多次執行
- 可靠性要建在驗證層，而不是只靠把溫度壓到零
> 回顧一下。模型輸出的是分數，取樣器才決定下一個 token；溫度控制分佈有多尖，top-p 控制候選的範圍。
> 溫度為零也不保證可以重現，所以評測要多次執行。思考練習會問你：寫程式的代理程式應該用多高的溫度？提示是：需要精確的產出偏低，需要多樣候選再挑選的時候偏高，但真正的可靠性，要建在測試、型別檢查這些驗證層上。
