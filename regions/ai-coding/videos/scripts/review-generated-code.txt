=== title
heading: 審查 AI 產生的程式碼
sub: 用「合併兩個已排序串列」做一次完整的審查
> 這一章用一個小例子，做一次完整的程式碼審查。請 AI 把兩個已排序的串列合併成一個，常會得到一段冗長但正確的程式；常見的改進建議，是換成一行內建排序。我們不只比較哪個比較短，而是用五個面向，加上可以執行的實驗，來做判斷。

=== table
heading: 審查的五個面向
| 面向 | 要問的問題 |
| 契約 | 輸入前提是什麼？違反時會怎樣？ |
| 語意邊界 | 空輸入、相等元素、輸入是否被改動？ |
| 效能 | 要實測，不要用直覺 |
| 可維護性 | 下一個人讀得懂嗎？ |
| 資源 | 額外記憶體、是否可串流？ |
> 審查有五個面向。契約：輸入的前提是什麼，違反的時候會怎樣。語意邊界：空輸入、相等的元素、輸入會不會被改動。效能：要實測，不要用直覺。可維護性：下一個人讀不讀得懂。資源：會不會用到額外的記憶體，能不能串流處理。

=== compare
heading: Lab 1：實測出的行為差異
col: 冗長版（兩指標合併）
- 其中一個輸入為空時，直接回傳輸入物件本身
- 相等時取第二個串列的元素
- 輸入沒排序時，輸出錯亂
col: 一行版（sorted(a + b)）
- 永遠回傳新的串列
- 穩定排序：相等時第一個串列在前
- 輸入沒排序時，默默修正
> 第一個實驗找出了行為差異。冗長版在其中一個輸入為空的時候，直接回傳輸入物件本身；呼叫端如果修改結果，會連帶改到原本的輸入，這就是別名問題。一行版永遠回傳新的串列。
> 第二個差異是相等元素的順序：冗長版在相等時取第二個串列的元素，而內建排序是穩定排序，會把第一個串列的元素放前面。這只有在元素帶著比較鍵以外的資料時才看得出來，例如依日期排序的事件紀錄。
> 第三，輸入沒有排序時，冗長版會輸出錯亂的結果，一行版則默默修好。要快速失敗還是容錯，應該由規格回答，而不是由實作隨機決定。

=== table
heading: Lab 2：效能要實測（各三十萬筆，CPython 3.13）
| 實作 | 耗時 |
| 兩指標合併 | 約 215 毫秒 |
| sorted(a + b) | 約 81.5 毫秒 |
| 標準庫 heapq.merge | 約 224.5 毫秒 |
note: 數字因機器而異，重點是相對關係；結論只對 CPython 與這種輸入成立
> 第二個實驗是效能。兩個串列各三十萬筆，手寫的兩指標合併大約兩百一十五毫秒，一行的內建排序大約八十一點五毫秒，標準庫的堆積合併大約兩百二十四點五毫秒。
> 這和大 O 的直覺相反。原因是這個語言的內建排序會辨認資料裡既有的遞增區段，用底層的程式合併；兩個已排序的串列接在一起，正好是兩段，所以實際上也接近線性，而且常數小得多。教訓不是內建一定比較快，而是用實測決定，並且記得結論只對這個執行環境和這種輸入成立。

=== bullets
heading: Lab 3：把審查結論寫成性質測試
- 性質：結果已排序、是新物件、不改動輸入、相等元素穩定
- 冗長版違反：別名、相等元素不穩定
- 一行版、帶 key 的 heapq.merge、依規格寫的版本：無違規
- 只定義小於比較的物件，用不帶 key 的 heapq.merge 會不穩定
> 審查的產出不該只是意見，而是可以重複執行的規格。第三個實驗把「已排序、是新物件、不改動輸入、相等元素穩定」寫成性質檢查，對五個實作各跑兩千次隨機輸入。
> 結果是：冗長版違反了別名與穩定性；一行版、帶比較鍵的堆積合併，以及依規格寫的版本，都沒有違規。還有一個意外的發現：物件只定義了小於比較的時候，不帶比較鍵的堆積合併，相等元素的順序並不穩定。這類細節，AI 的輸出和你的直覺都不會主動告訴你，要靠性質測試抓出來。

=== bullets
heading: 該不該讓 AI 寫：成本模型
- 委派的條件：說明＋審查＋修正＋漏網缺陷的期望成本 ＜ 自己寫
- 說明容易、驗證便宜的任務穩賺
- 說明困難、邊界很多、驗證昂貴的任務常常不划算：時區、金額、併發
> 最後是要不要讓 AI 寫的成本模型。只有當說明、審查、修正，加上漏網缺陷的期望成本，小於自己寫的成本，才值得委派。說明容易、驗證便宜的任務穩賺，例如格式轉換、樣板、有明確規格的小函式；說明困難、邊界很多、驗證昂貴的任務常常不划算，例如時區、金額與併發。

=== quiz
heading: 檢查點
q: 哪一項是冗長版有、而 sorted(a + b) 沒有的行為風險？
- 結果可能沒有排序
- 時間複雜度是 O(n²)
- * 其中一個輸入為空時，回傳值與輸入是同一個物件，修改結果會改到輸入
- 遇到空串列會丟出例外
> 檢查點：哪一項是冗長版有、一行版沒有的行為風險？答案是第三個，別名問題。其他選項都不是事實：兩者在符合前提的輸入下都會排序，都是線性或接近線性，也都不會因為空串列丟出例外。

=== end
heading: 重點回顧
- 「更短」不是審查結論；五個面向才是
- 效能主張要實測，並標明環境
- 審查結論要寫成性質測試與規格
> 回顧一下。更短不是審查結論，五個面向才是；效能主張要實測，並標明環境；審查的結論，要寫成性質測試與規格。這一章頁面上有完整的程式碼與輸出，建議你親手跑一次。
> 思考練習會請你寫出，要求同事補進合併請求的規格與測試，並指出哪一項最容易被漏掉。
