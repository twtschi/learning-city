=== title
heading: 術語表
sub: 第一週用到的十幾個核心名詞，一次串起來
> 這一章是第一週的術語表。我們不逐條背定義，而是把這些名詞放回一次請求的生命週期裡：輸入怎麼被切開、模型怎麼算、怎麼選字、怎麼加速，以及外面那一層程式在做什麼。
> 這些名詞分成四組：輸入與上限、怎麼選下一個 token、推論與效能，以及模型以外的那一層。

=== table
heading: 輸入與上限
| 術語 | 一句話定義 |
| Token | tokenizer 切出的子字串，對應詞表中的整數 ID |
| Context window | 單次請求輸入加輸出的 token 上限 |
| Prompt caching | 重用相同前綴的處理結果，降低成本與延遲 |
> 每個術語都只用一句話定義，重點是知道它出現在流程的哪一段。
> 先從輸入開始。token 是切詞器切出來的子字串，每一段對應詞表裡的一個整數，也是計費與上下文的單位。上下文視窗是一次請求裡，輸入加輸出的 token 上限。提示詞快取則是重用相同前綴的處理結果，用來降低成本與延遲；前提是前綴完全相同。
> 要注意，上下文視窗算的是輸入加輸出的總和。模型要寫出來的內容，也佔用同一個上限。

=== table
heading: 模型怎麼選下一個 token
| 術語 | 一句話定義 |
| Logit / Softmax | 模型輸出的原始分數，以及把分數轉成機率的函數 |
| Temperature | 取樣前對分數的縮放；越低分佈越尖，越高越平 |
| Top-p | 只在累積機率達 p 的最小候選集合中取樣 |
> 接著是選字。原始分數是模型對每個候選算出的分數，歸一化函數把分數轉成機率分佈。溫度是取樣前對分數的縮放，越低分佈越尖，越高越平。top-p 是累積機率取樣：只在累積機率達到門檻的最小候選集合裡抽。
> 這兩個旋鈕的分工可以這樣記：溫度改變分佈的形狀，top-p 限制候選的範圍。

=== table
heading: 推論與效能
| 術語 | 一句話定義 |
| Prefill / Decode | 處理輸入的階段，與逐 token 生成輸出的階段 |
| KV cache | 保留已處理 token 的 key 與 value，避免重算 |
| TTFT / TPOT | 首個 token 的延遲，以及之後每個 token 的間隔 |
| GQA / MQA | 多個 query head 共用較少的 KV head，降低 KV cache 大小 |
| Continuous batching | 請求隨時加入與離開批次，提高硬體使用率 |
> 再來是推論與效能。預填是處理輸入的階段，解碼是逐個詞元生成輸出的階段。鍵值快取保留每個已處理詞元的鍵與值，避免重新計算。
> 延遲常用兩個指標：首個詞元的延遲，以及之後每個詞元之間的間隔。分組查詢注意力和多查詢注意力，是讓多個查詢頭共用較少的鍵值頭，以縮小鍵值快取。持續批次處理則讓請求隨時加入與離開批次，提高硬體的使用率。
> 有兩個名詞都帶著快取，很容易混淆。鍵值快取保留的，是已處理詞元的鍵與值；提示詞快取重用的，是相同前綴的處理結果。

=== table
heading: 模型以外的那一層
| 術語 | 一句話定義 |
| Tool use | 模型以結構化區塊請求呼叫工具，由 harness 驗證並執行 |
| Harness | 包住模型的程式：組 context、執行工具、做驗證與限額 |
| Eval | 用可重複的測試集與指標衡量系統好壞 |
> 最後是模型以外的那一層。工具使用，是模型用結構化的區塊請求呼叫工具，由 harness 驗證並執行。harness 是包住模型的程式，負責組上下文、執行工具、做驗證與限額。評測，則是用可重複的測試集與指標，衡量整個系統的好壞。
> 特別注意工具使用的分工：提出請求的是模型，驗證並執行的是 harness。評測的關鍵字是可重複：用同一組測試集與指標，來衡量系統的好壞。

=== steps
heading: 把名詞串成一次請求
- harness 組出 context，切成 token；相同前綴命中 prompt cache
- prefill 處理輸入、建立 KV cache；decode 逐個產生 token
- 每一步由 temperature 與 top-p 決定取樣
- 模型提出 tool use，harness 驗證、執行、回送結果
- 用 eval 衡量整個流程的品質、成本與延遲
> 先看一個具體的情境：你在開發環境裡請代理程式修一個測試失敗。它的每一輪請求，都會經過下面這五步。
> 現在把這些名詞串成一次請求。harness 組出上下文，切成詞元；如果前綴相同，就命中提示詞快取。預填階段處理輸入、建立鍵值快取；解碼階段逐個產生詞元，每一步由溫度與 top-p 決定怎麼取樣。
> 當模型提出工具呼叫，harness 驗證、執行、把結果送回去。最後，用評測來衡量整個流程的品質、成本與延遲。能把這段話講順，第一週的名詞就真的串起來了。

=== end
heading: 重點回顧
- 輸入：token、context window、prompt caching
- 選字：logit、softmax、temperature、top-p
- 效能：prefill、decode、KV cache、TTFT、batching
- 系統：tool use、harness、eval
> 回顧一下：輸入相關的是詞元、上下文視窗與提示詞快取；選字相關的是原始分數、歸一化函數、溫度與 top-p；效能相關的是預填、解碼、鍵值快取、延遲指標與批次處理；系統層則是工具使用、harness 與評測。
> 一個實用的自我檢查：拿一次真實的代理程式紀錄，試著指出每一段時間花在預填還是解碼、哪些輸入命中了快取、哪一步是工具呼叫，你就會發現這些名詞都是可以量測的東西。
> 這一章沒有檢查題，讀完術語表之後，請自己標記完成。
