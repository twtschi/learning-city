Context window 是一次請求「輸入加輸出」的上限，但「放得下」不等於「用得好」。已有研究（例如 2023 年的〈Lost in the Middle〉）顯示，模型對長輸入中間位置的資訊，取用品質可能比開頭與結尾差；實務上也常見無關內容越多、答案越容易被干擾。這些行為會隨模型版本改變，**要用你自己的任務去量**。

設計 coding agent 時，把 context 當成預算來管理：

1. **常駐內容要精簡**：system prompt、工具定義、專案規則每一輪都會付費，越短越好。
2. **按需載入**：不要預先塞整個 repo。讓 agent 用搜尋與讀檔工具在需要時取得，並限制單次讀取的行數。
3. **工具輸出要截斷與摘要**：一個吐出 5 萬行的測試日誌會直接擠掉重要資訊。回傳錯誤摘要、前後各 N 行，並提供取得完整輸出的方法。
4. **壓縮歷史**：長任務到一定長度後，把舊的對話與工具結果摘要成「已完成什麼、尚待什麼、關鍵決定與檔案」，再繼續。壓縮本身會丟資訊，所以決定要保留的欄位要明確。
5. **把獨立的探索交給 subagent**：它在自己的 context 裡讀很多檔案，只回傳結論，主對話就不會被雜訊污染。
