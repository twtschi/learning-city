# 架構與拓撲

## 一句話模型

PCIe 是保留 PCI 軟體模型、改用「序列、點對點、全雙工、封包式」傳輸的交換式互連。軟體仍以 Bus/Device/Function、Configuration Space 與 BAR 管理裝置；硬體連線則不再是所有裝置共享同一條平行匯流排。〔BOOK p.98-107；BP p.2-3〕

## 為何從 PCI/PCI-X 轉向 PCIe

PCI/PCI-X 的共享平行匯流排會遇到：

- 多裝置共享頻寬，需要中央仲裁，一次只能由一個 Bus Master 使用匯流排。
- 位址與資料多工、turn-around cycle、retry/disconnect 等機制降低效率。
- 隨頻率上升，clock skew、signal skew、反射、負載數與走線長度更難控制。
- 平行匯流排腳位多，擴充頻寬常伴隨成本與拓撲限制。

PCIe 把每一段連線改成兩個裝置間的專用 Link；資料與控制資訊被封裝在封包中，Switch 可同時處理不同埠之間的流量。這是 switched fabric，不是共享 bus。〔BOOK p.68-97、98-105；BP p.2-3〕

## Link、Lane、方向與頻寬

- **Link**：兩個 PCIe Port 之間的點對點連線。
- **Lane**：一組發送差動對加一組接收差動對，可同時雙向傳輸。
- **Link Width**：x1、x2、x4、x8、x12、x16、x32；增加 Lane 數可線性增加理論頻寬。
- **Gen1**：2.5 GT/s，8b/10b；每 Lane 單方向有效資料率約 250 MB/s。
- **Gen2**：5.0 GT/s，8b/10b；每 Lane 單方向約 500 MB/s。
- **Gen3**：8.0 GT/s，128b/130b；每 Lane 單方向約 985 MB/s，常近似為 1 GB/s。

原書的 aggregate bandwidth 把雙向同時計入，因此 Gen3 x16 列為 32 GB/s；討論效能時必須先說清楚是「單方向」或「雙向合計」。〔BOOK p.102、105；BP p.13〕

## 倒樹狀拓撲

PCIe 為了維持 PCI 軟體相容性，採簡單倒樹狀階層，不允許任意迴圈。CPU/Host 在樹根，裝置位於下游。〔BOOK p.107；BP p.3〕

| 元件 | 角色 | 重要特性 |
|---|---|---|
| Root Complex (RC) | CPU/Memory 與 PCIe fabric 的介面 | 代表處理器發出交易；Root Port 是拓撲入口 |
| Root Port | RC 對外的 PCIe Port | 對軟體呈現 Type 1 Header/虛擬 PCI-to-PCI Bridge |
| Switch | Fan-out、aggregation、TLP routing | 一個 Upstream Port、多個 Downstream Port；每個 Port 含自己的 Link 層與 PHY |
| Endpoint | 最終功能裝置 | 例如 NVMe、NIC、GPU；外部點對點 Link 上通常是 Device 0 |
| Bridge | 連接 PCIe 與其他 bus | 例如 PCIe-to-PCI/PCI-X；保留舊裝置相容性 |
| Function | 軟體可獨立設定的邏輯功能 | 每個 Function 有自己的 Configuration Space 與 BDF |

## 三層協定疊

### Transaction Layer

把裝置核心的讀寫、設定或訊息意圖組成 TLP；在接收端解碼 TLP，完成路由、排序、Flow Control 類別與 Request/Completion 關聯。TLP 的主要 Request 類別是 Memory、I/O、Configuration、Message。〔BOOK p.118-130；BP p.4-6〕

### Data Link Layer

保證「單一 Link 上」的可靠傳輸。它為 TLP 加上 Sequence Number 與 LCRC，使用 Ack/Nak DLLP 和 Replay Buffer 做自動重送，也承載 Flow Control 與部分 Power Management DLLP。〔BOOK p.131-135、366-417；BP p.8-10〕

### Physical Layer

負責 framing、striping、scrambling、encoding、serialization、clock recovery、lane alignment、link training 與電氣訊號。Gen1/2 與 Gen3 的邏輯編碼不同。〔BOOK p.135-138、420-703；BP p.12-13〕

> 層是責任邊界，不強迫晶片內部一定照三個實體模組切割。〔BOOK p.113〕

## 三種在 Link 上出現的流量

| 類型 | 產生/終止層 | 是否跨 Switch 路由 | 用途 |
|---|---|---|---|
| TLP | Transaction Layer | 是 | Memory/I/O/Configuration/Message 交易 |
| DLLP | Data Link Layer | 否，只在相鄰兩 Port 間 | Ack/Nak、Flow Control、Power Management |
| Ordered Set | Physical Layer | 否，只在相鄰 PHY 間 | Training、clock compensation、electrical idle 等 |

只有 TLP 會穿越多個 Link；DLLP 與 Ordered Set 到每一跳即被消耗。這是理解「端到端交易」與「逐跳可靠性」的關鍵。〔BOOK p.206、225〕

## 一次 Memory Read 的端到端視角

1. Requester 的核心提出目標位址、長度與屬性。
2. Transaction Layer 建立 Memory Read Request TLP；Memory Read 是 Non-Posted。
3. Data Link Layer 加 Sequence Number/LCRC，並保留副本等待 Ack。
4. Physical Layer striping、scrambling、encoding 後送上 Lane。
5. 每一跳先做 PHY/Data Link 檢查與 Ack/Nak；Switch 再依 TLP 位址路由。
6. Completer 取得資料，產生一個或多個 Completion with Data TLP。
7. Completion 依 Requester ID 返回，Requester 用 Transaction ID 對應原始 Request。

這個流程把三種不同可靠性問題分開：PHY 處理訊號、Data Link 處理逐跳錯誤、Transaction Layer 處理端到端語意。〔BOOK p.124、140-143、208；BP p.15〕
