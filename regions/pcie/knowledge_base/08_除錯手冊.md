# PCIe 3.0 除錯手冊

## 原則：先定位層，再解碼細節

PCIe trace 已經過 serializing、encoding、scrambling 與 multi-lane striping；只看示波器波形通常無法直接讀出 TLP。Protocol analyzer 需處理 lane skew、polarity、lane reversal、descrambling、decoding 與 packet reconstruction。〔BOOK p.976-993；BP p.14〕

## 分層決策樹

```text
裝置完全看不到
  -> Power / clock / PERST#
  -> Detect 是否看到 receiver termination
  -> LTSSM 是否到 L0
  -> Configuration Read 是否收到 UR/CRS/SC

裝置可枚舉但驅動無法啟動
  -> BAR / bridge windows / Command bits
  -> MSI/MSI-X / reset state / device-specific init
  -> UR / CA / Completion Timeout / AER

可運作但不穩或效能差
  -> negotiated speed/width
  -> Flow Control credits / VC / ordering
  -> LCRC, Nak, Replay, Recovery 次數
  -> ASPM / L0s / L1 進出
  -> Gen3 equalization / signal integrity
```

## 1. Link bring-up

記錄：

- LTSSM 最後狀態與反覆跳轉路徑。
- Advertised 與 negotiated speed/width。
- 哪些 Lane active；是否發生 lane reversal/polarity inversion。
- TS1/TS2 中的 Link/Lane number、speed change、equalization control。
- 是否只能 Gen1、只能降寬，或進 Recovery 後才失敗。

判讀：

- 卡 Detect：先查 termination、電源、參考時鐘、PERST#、連接器與 Lane 對。
- 卡 Polling：查 bit/symbol/block lock、training ordered sets 與 signal quality。
- 卡 Configuration：查 Link/Lane numbering、de-skew、width negotiation。
- L0 後反覆 Recovery：查速度切換、Gen3 equalization、BER、電源狀態退出。

〔BOOK p.564-703〕

## 2. Enumeration

最小 trace：

1. Configuration Read Vendor ID。
2. Completion Status 與資料。
3. Header Type / multifunction bit。
4. Bridge Primary/Secondary/Subordinate Bus Number 寫入。
5. 深度優先探測順序。
6. BAR sizing 與 BAR base 寫回。

異常分類：

- `FFFFh` + UR：常是該 BDF 不存在，enumeration 中可能正常。
- CRS：裝置存在但未就緒；確認 Root/軟體重試策略與時序。
- Completion Timeout：路徑、Link 或 Completer 行為異常。
- Bus number/window 錯：下層裝置可能完全無法再被探測。

〔BOOK p.163-175〕

## 3. 地址與 TLP 路由

檢查：

- Type 0/Type 1 Header 是否符合 Function 類型。
- BAR 的 size/type/prefetchable/64-bit 解讀是否正確。
- Endpoint BAR address 與每層 Bridge Base/Limit 是否包含。
- 32-bit address 使用 3DW、64-bit address 使用 4DW。
- Switch ingress/egress 方向是否符合 Address/ID/Implicit routing 規則。

典型錯誤：BAR 配到位址，但上游任一 Bridge window 未開；此時 driver 看到 BDF，卻對 MMIO 存取得到 UR 或 timeout。〔BOOK p.180-225〕

## 4. Request/Completion 配對

對每個 Non-Posted Request 建表：

| 欄位 | 用途 |
|---|---|
| Requester ID + Tag | 與 Completion 配對 |
| Address + Length + Byte Enable | 預期資料範圍 |
| TC + Attr | ordering / VC / snoop 語意 |
| Timestamp | 計算 completion latency/timeout |
| Completion Status | SC、UR、CRS、CA |
| Byte Count + Lower Address | 重組多個 Completion |

不要假設一個 Read 只對一個 Completion。Tag 未釋放、Completion 重複/遺失或 Byte Count 不連續，都可能造成 timeout 或資料重組錯誤。〔BOOK p.243-261〕

## 5. Flow Control 與效能

同時看 PH/PD/NPH/NPD/CPLH/CPLD：

- 哪一類 credit 為零？
- UpdateFC 是否持續返回？
- 是 receiver buffer 未釋放，還是 DLLP 遺失/timeout？
- 多個 TC 是否全映射 VC0，造成 head-of-line blocking？
- arbitration 是否讓低優先 VC 飢餓？

只看 Link utilization 無法區分「沒有工作」「沒 credit」「等待 Completion」「Replay 中」或「低功耗狀態」。〔BOOK p.274-343〕

## 6. Ack/Nak、Replay 與 BER

建立時間線：TLP Sequence Number -> Ack/Nak -> Replay Timer -> Replay -> Recovery。

- Nak 緊跟 LCRC/sequence error：較像實際傳輸錯誤。
- 沒有 Nak，但 Replay Timer 到期：可能 Ack DLLP 遺失或對端回饋異常。
- Replay 成功且不頻繁：Data Link 機制正常修復。
- Replay storm、反覆 Recovery、降速後消失：強烈指向 PHY/channel margin。

〔BOOK p.376-417〕

## 7. Error/AER 收斂

收集順序：

1. Root Port 與 Endpoint 的 AER Correctable/Uncorrectable Status。
2. Mask、Severity、First Error Pointer。
3. Header Log 與 Error Source ID。
4. Link Status、Device Status、Root Error Status。
5. 同一時間的 analyzer trace 與 LTSSM/Replay 計數。

清 status 前先保存完整快照；RW1C bit 清掉後，第一次錯誤線索可能無法還原。〔BOOK p.706-761〕

## 8. Reset/Power/Hot Plug

若問題只在 resume/reset/hot plug 後出現：

- 確認 reset 類型（Fundamental/Hot/FLR）與影響範圍。
- 檢查裝置 context、BAR、MSI/MSI-X、Bus Master、AER 是否需重設。
- 對照 D-state 與 L-state，不把 Function off 和 Link low-power 混為一談。
- 關閉 ASPM 做 A/B test 只能定位方向，不應當成最終原因。
- Surprise removal 要檢查 pending transactions、error containment 與 driver teardown。

〔BOOK p.762-945〕
