# 資料連結層

## 責任邊界

Data Link Layer 的核心任務是讓 TLP 在「一段 Link」上可靠送達。它不決定端到端路由，也不保證裝置功能已完成；每經過一個 Switch Port，前一跳的 Data Link 封裝結束，下一跳重新產生 Sequence Number/LCRC。〔BOOK p.366-417；BP p.9-10〕

## TLP 在 Data Link Layer 的封裝

```text
[12-bit Sequence Number carried in 2 bytes] [TLP] [32-bit LCRC]
```

Transmitter：

1. 為新 TLP 指派下一個 Sequence Number。
2. 計算涵蓋 Sequence Number、Header、Payload、ECRC 的 LCRC。
3. 把封裝後 TLP 的副本留在 Replay Buffer。
4. 傳送並等待 Ack；收到對應 Ack 才能清除已確認項目。

Receiver：

1. 檢查 Physical Layer 錯誤、LCRC 與 Sequence Number。
2. 正確且符合預期序號的 TLP 交給 Transaction Layer，排程 Ack。
3. 錯誤或遺失序號時丟棄問題資料並排程 Nak。
4. 重複 TLP 不重複交付上層，但可回 Ack 幫助對端收斂。

〔BOOK p.231-233、376-406〕

## DLLP

DLLP 是固定 8 bytes 的 Data Link Layer packet，主要類型：

- Ack / Nak。
- InitFC / UpdateFC（Flow Control）。
- Power Management DLLP。
- Vendor-specific DLLP。

DLLP 到相鄰 Port 的 Data Link Layer 就終止，不經 Switch 路由，不受 Flow Control，也沒有 DLLP 自身的 Ack/Nak。它以 16-bit CRC 檢查；錯誤 DLLP 直接丟棄，靠週期性重送或 timeout 恢復。〔BOOK p.366-375、225；BP p.9〕

## Sequence Number 的滑動視窗

Sequence Number 是 12 bits，範圍 0-4095，之後 rollover。比較時要用模數/視窗語意，不能把 0 永遠視為比 4095 小。Transmitter 必須限制未確認範圍，避免 rollover 後新舊序號模糊。〔BOOK p.379、388〕

## Ack 與 Nak

- **Ack**：累積確認，AckNak_Seq_Num 表示至該序號為止已正確收到。
- **Nak**：指出從接收端期待序號開始需要 replay。
- Ack 可延遲/合併以降低 DLLP overhead，但受 AckNak latency timer 限制。
- Nak 或 Replay Timer timeout 會觸發 Replay Buffer 內容重送。

〔BOOK p.376-406；BP p.10〕

## Replay Buffer

Replay Buffer 必須保留所有「已送出但尚未 Ack」的 TLP。收到累積 Ack 後可移除已確認項目；收到 Nak 或 timeout 時，暫停送新 TLP並從指定位置 replay。若反覆 replay 仍無法恢復，會升級成 Data Link Protocol Error。〔BOOK p.379-406〕

## LCRC、ECRC、DLLP CRC

| CRC | 大小 | 保護對象 | 生命週期 |
|---|---:|---|---|
| LCRC | 32 bits | Data Link 封裝後的 TLP | 每一 Link 重新產生與檢查 |
| ECRC | 32 bits | Transaction Layer 的端到端 TLP 內容 | 可跨 Switch 保留至最終接收端 |
| DLLP CRC | 16 bits | DLLP 本身 | 單一 Link；壞 DLLP 丟棄 |

## 正常與異常案例

### 正常

TLP 10、11、12 到達，Receiver 累積回 Ack 12；Transmitter 可從 Replay Buffer 一次清掉三個。

### TLP/LCRC 錯誤

Receiver 期待 11 卻檢到錯誤，丟棄並回 Nak 10；Transmitter 從尚未確認的下一筆開始 replay。

### Ack 遺失

Ack 本身 CRC 錯而被丟棄，不代表 TLP 未送達。後續累積 Ack 可一次確認更多 TLP；若一直沒有新 Ack，Replay Timer 到期後 Transmitter 重送，Receiver 辨識 duplicate、丟棄副本並再回 Ack。〔BOOK p.406〕

## 除錯判斷

看到大量 Replay 時先問：

1. 是 LCRC/Physical error 導致 Nak，還是 Ack 遺失導致 timeout？
2. 是否集中在單一 Lane、速度、方向或電源狀態切換後？
3. Replay 後是否成功，或最後轉成 Data Link Protocol Error/Link Recovery？
4. Flow Control credit 是否正常？不要把「不能送」誤判成「送了又錯」。
