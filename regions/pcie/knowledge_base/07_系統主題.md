# 系統主題

## Error Detection and Handling

PCIe 把錯誤處理拆成四件事：Detection、Logging、Reporting、Signaling。偵測到錯誤不代表一定會通知 Root；是否記錄、遮罩、改變 severity 或傳送 Error Message 由能力與設定決定。〔BOOK p.706-761〕

### Baseline 與 AER

- **Baseline Error Reporting**：所有 PCIe 裝置必須支援，保留 PCI 相容狀態與基本 PCIe 錯誤資訊。
- **Advanced Error Reporting (AER)**：可選 extended capability，細分 correctable/uncorrectable status、mask、severity、First Error Pointer、Header Log 等。

〔BOOK p.709-761〕

### 嚴重度

| 類別 | 意義 | 常見反應 |
|---|---|---|
| Correctable | 硬體已恢復，資料/協定可繼續 | 記錄、計數、ERR_COR；例如 receiver error、replay 類事件 |
| Uncorrectable Non-Fatal | 該交易受影響，但 Function/Link 可能繼續 | ERR_NONFATAL、驅動/OS 復原 |
| Uncorrectable Fatal | Link/Function 狀態可能不可靠 | ERR_FATAL、reset/recovery/isolation |

實際分類與升級受 AER severity 設定及 agent role 影響。〔BOOK p.706-750〕

### 錯誤保護層次

- PHY：解碼、framing、lock、electrical error。
- Data Link：LCRC、Sequence、Replay，處理逐跳可恢復錯誤。
- Transaction：Malformed TLP、UR、CA、Completion Timeout、ECRC、Poisoned TLP。
- Software/AER：記錄來源、嚴重度、header，決定 reset/隔離策略。

若 Link 已壞到下游無法回報，上游 Port 必須代表該 Link 回報；軟體可嘗試 retrain。〔BOOK p.742〕

## Power Management

### Function D-state 與 Link L-state 是兩條軸

- **D0/D1/D2/D3hot/D3cold**：Function 的電源/功能狀態。
- **L0/L0s/L1/L2/L3**：Link 的傳輸/低功耗狀態。

Function state 與 Link state 有合法組合及轉換條件，但不能把 D3 與 L1 當成同一件事。系統由 OS、PCIe bus driver、device driver、firmware/ACPI 分工。〔BOOK p.762-851〕

### ASPM 與軟體導向 PM

- ASPM 可在 Link 閒置時硬體自動進入 L0s/L1。
- 軟體導向 Link PM 透過 PM handshake 協調更深狀態。
- 更深狀態通常節能更多，但退出 latency 更大，且可能需要更多 context restore/retraining。
- PME 讓裝置在低功耗狀態請求喚醒系統。

〔BOOK Ch.16；BOOK p.564-703〕

## Interrupt

| 方法 | 形式 | 特性 |
|---|---|---|
| Legacy INTx emulation | Assert/Deassert INTx Message | 為 PCI 相容保留，level-like 語意 |
| MSI | Memory Write TLP | In-band、可配置 message address/data |
| MSI-X | Memory Write TLP + table/PBA | 更多 vectors、逐 vector mask、較適合高效能多佇列裝置 |

PCIe 不需要實體 INTx pin 穿越 Link；MSI 支援在 PCIe 裝置中是核心要求，實務上優先使用 MSI/MSI-X。〔BOOK p.852-891〕

## Reset

原書描述四類：

- **Cold Reset**：移除再恢復 main power 的 Fundamental Reset。
- **Warm Reset**：不移除 main power 的 Fundamental Reset，可透過 PERST# 或內部事件。
- **Hot Reset**：透過 training sequence 在 Link 內傳播，針對下游 hierarchy。
- **Function-Level Reset (FLR)**：只重設單一 Function，盡量不影響同裝置其他 Function 或整條 Link。

Reset 後要重新考慮 Configuration Space、BAR、bus mastering、MSI/MSI-X、AER、device-specific context 與 link training。〔BOOK p.892-905〕

## Hot Plug 與 Power Budgeting

Hot Plug 不只是 presence detect；完整模型涉及：

- Attention Button/Indicator、Power Controller、Latch/Interlock、Presence Detect。
- Slot Capability/Control/Status。
- 插入/移除事件通知與 OS 協調。
- surprise removal 能力與錯誤隔離。
- Slot Power Limit Value/Scale 與 Set Slot Power Limit Message。

軟體與 firmware 依系統電源及散熱能力設定 slot power limit；卡在被配置/允許前不應超出初始限制。〔BOOK p.906-945〕

## 2.1 更新與 3.0 範圍提醒

MindShare 書把 Resizable BAR、ARI/IDO、AtomicOp、LTR、OBFF、Multicast 等演進內容散布在各章，並在 Chapter 20 彙整 2.1 更新。閱讀時要分辨：

- PCIe 基本必備能力。
- 某版本新增但可選的 capability。
- 平台/裝置宣告後才成立的行為。

不要因為書中描述某功能，就假設所有 PCIe 3.0 裝置都實作或啟用。〔BOOK p.946-975〕
